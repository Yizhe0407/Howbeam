# 專案系列（Series）

> 規劃文件，還沒有實作。

## 一句話

**系列是 Library 層級的資料夾**：把同一套系統的多個專案排在一起，可以一起管理、一起匯出。專案本身完全不變，跟專案裡的章節（section）無關。

---

## 為什麼要做

一個系統的操作說明常常拆成好幾份（例如 HR、Reviewer、Reviewee 各一份）。現在只能一份一份找、一份一份匯出。

同類工具大多只做到「資料夾分類」，匯出仍然一次一份（Tango、Scribe、iorad）。Guidde 的播放清單可以整份匯出，但只匯出成 SCORM。**能把多份指南合成一份文件的工具很少**，這是 Howbeam 可以做出差異的地方。

---

## 規則

| 規則 | 說明 |
| --- | --- |
| 一個專案最多屬於一個系列 | 這樣 Library 才能「在系列裡就只顯示系列」，不會重複出現 |
| 系列內的專案有順序 | 順序就是合併匯出的順序 |
| 系列可以是空的 | 先建系列再慢慢加入專案 |
| 刪除系列不會刪除專案 | 專案回到 Library 單獨顯示 |
| 刪除專案會自動移出系列 | 不留下壞掉的參照 |
| 系列內不能再放系列 | 只有一層，保持簡單 |

---

## 畫面

**原則：操作越少越好，文字越短越好。** 每個畫面只留必要的按鈕，次要動作收進「⋯」選單；不放說明段落，靠按鈕名稱就看得懂。

### Library

- 系列卡片和專案卡片**混在同一個格狀清單**裡。
- **已經在系列裡的專案不單獨顯示**，只顯示它所屬的系列卡片。不在系列裡的專案照舊顯示。
- 排序：照「最近修改」。系列的修改時間取「系列本身」和「裡面任一專案」中最新的那個。系列**不固定置頂**，因為使用者通常是要回去繼續最近在做的東西。
- 系列卡片：疊起來的封面（第一個專案的縮圖）、系列名稱（可直接編輯，共用 `EditableTitle`）、「N 個專案」、按鈕「開啟」「解散系列」（先確認）。第 2 階段再加「匯出」。
- 頁首「新系列」：建立未命名系列並直接打開，名稱在系列頁改。
- 點進系列 → 系列頁（網址 `#series=<id>`，瀏覽器上一頁可回專案庫）：專案清單（拖曳排序）、「加入專案」。每列只有「開啟」和「移出系列」。拖曳把手可用鍵盤操作（空白鍵提起、方向鍵移動），不另做上移／下移。
- 只有一個動作就直接放按鈕，不收進「⋯」。
- 專案卡片加「加入系列」按鈕：選現有系列，或輸入名稱新建一個。
- 搜尋：也比對系列名稱。比對到系列裡的專案時，顯示該系列卡片。

### Popup（錄製目標選單）

Popup 選的是「要錄進哪個專案」，**目標一定是專案，不能是系列**。所以這裡**不收合成系列**，否則每次都要多點一層。

- 照舊列出最近 5 個專案。
- 在專案名稱下方用小字標出所屬系列，例如「M-Role Performance」。
- 選單最上方仍然是「新專案」。之後可考慮加「在系列中新增專案」，錄完自動放進那個系列（第二階段）。

## 匯出

系列的匯出按鈕提供兩種方式：

| 方式 | 產出 | 適合 |
| --- | --- | --- |
| **合併成一份** | 一份 PDF / HTML / Markdown。每個專案是第一層標題，專案原本的章節排在它底下 | 交給使用者的完整手冊 |
| **各自一份** | 一個 ZIP，裡面每個專案一份檔案，檔名前面加順序編號（`01-HR.pdf`） | 想分開發給不同角色 |

### 合併匯出的排版

```
系列名稱（封面標題）
├─ 專案 A          ← 第一層標題，PDF 書籤第 1 層
│  ├─ 章節 1       ← 第二層，書籤第 2 層
│  │  └─ 步驟…
│  └─ 章節 2
└─ 專案 B
   └─ 步驟…（沒有章節的專案直接接步驟）
```

- PDF 排版本來就有 1～3 層標題，書籤也能巢狀（`lib/export/pdf/pdf-layout.ts` 的 `PdfOutlineEntry`）。要做的是把現有的「章節 = 第 1 層」整體往下推一層。
- 頁尾標題改用系列名稱。
- 每個專案從新的一頁開始。

### 上限

PDF 有頁數和檔案大小上限（`PROJECT_EXPORT_LIMITS.maxPdfPages` / `maxPdfBytes`），系列很容易超過。

- 匯出前先用各專案的步驟數估算，超過就提示「改用各自一份」。
- 實際產生時超過，照現在的錯誤處理顯示訊息，不產出殘缺的檔案。

## 資料

新增一個 IndexedDB store `series`：

```ts
interface ProjectSeries {
  id: string;
  title: string;
  /** 有順序；順序就是合併匯出的順序。 */
  projectIds: string[];
  createdAt: number;
  updatedAt: number;
}
```

- 順序只存在系列這一邊，專案不用改 schema。
- 「一個專案最多一個系列」在寫入時檢查（同一個 transaction 讀所有系列）。
- 刪除專案時，在同一個 transaction 裡把它從系列移除。
- 系列寫入後呼叫 `notifySeriesChanged()`（獨立的 channel），讓 Library 和 popup 即時更新。不借用專案的通知，避免喚醒編輯器重新載入和資料夾備份。

## 檔案格式與舊版相容

### 原則

**專案封存檔（`.howbeam`，v4）完全不動。** 系列用自己的正式格式，有自己的 `format`、`version` 和驗證，不用補丁。

### 為什麼不把系列寫進專案封存檔

匯入時會先檢查 `format` 和 `version`（`project-archive-import.ts`），metadata 也是白名單驗證（`assertExactKeys`）。加入 `seriesId` 就要升到 v5，舊版會整個檔案拒絕匯入，連跟系列無關的步驟也救不回來。

### 系列格式 `howbeam-series`

副檔名 `.howbeam-series`，兩種內容：

| 用途 | 內容 |
| --- | --- |
| 分享、搬移 | 系列名稱、順序，加上每個專案的完整內容（等於多個專案封存檔包在一起） |
| 資料夾備份 | 只有系列名稱、順序和專案 id。專案本身已經各有一份 `.howbeam`，不重複存截圖 |

匯入時：
- 完整版：建立所有專案，再建立系列。
- 備份版：只連結已經存在的專案；找不到的專案跳過，並告訴使用者少了哪些。

### 舊版會遇到什麼

| 情況 | 結果 |
| --- | --- |
| 舊版匯入新版匯出的 `.howbeam` | 正常（格式沒變） |
| 舊版匯入 `.howbeam-series` | 檔案選擇器選不到；硬選也只會顯示格式錯誤，不會壞資料 |
| 舊版讀新版的備份資料夾 | 專案照常還原，系列資訊被忽略 |
| 新版開過後再裝回舊版 | IndexedDB 不能降版，舊版會打不開資料庫。Web Store 不會降版，只有手動載入舊 build 才會遇到；這是所有 schema 升級的共同限制，不是系列造成的 |

### 資料庫

`DATABASE_VERSION` 3 → 4，新增 `series` store。`projects` 和 `steps` 不改，舊資料不用轉換。

## 分階段

| 階段 | 內容 |
| --- | --- |
| 1 | `series` store、Library 系列卡片和系列頁、加入／移出／排序、popup 顯示系列名稱 |
| 2 | 系列匯出：各自一份（ZIP） |
| 3 | 系列匯出：合併成一份（PDF / HTML / Markdown） |
| 4 | `howbeam-series` 格式：系列匯出／匯入、資料夾備份與還原；在系列中直接新增專案 |

第 2 階段比第 3 階段簡單很多（只是迴圈呼叫現有匯出再打包），可以先上。

---

## 先不做

- 系列說明文字（description）：系列只有名稱。
- 合併匯出的目錄頁：PDF 用書籤導覽就好。
